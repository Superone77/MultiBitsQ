# 混合精度进化搜索算法（理论说明）

本文档从算法层面概述 `ParetoQ/evolution.py` 的混合精度搜索流程，强调抽象步骤与设计权衡。

## 问题建模
- **搜索空间**：每个可量化层有一组候选 bit（如 2/3/4），整体是一组离散向量 `b = (b₁, …, b_L)`。
- **目标函数**：在给定验证集上最小化困惑度 `PPL(b)`（或等价的平均损失）；可选约束：
  - 平均比特上限：`(Σ pᵢ·bᵢ) / Σ pᵢ ≤ B_avg`
  - 总比特上限：`Σ pᵢ·bᵢ ≤ B_total`
 其中 `pᵢ` 是第 `i` 层权重参数量，用作粗粒度的模型大小/算力 proxy。

## 算法框架（进化搜索）
1. **个体编码**：一条染色体即一组 layer→bit 分配向量 `b`。
2. **适应度评估**：将 `b` 应用到模型，关闭随机 bit/噪声，前向计算验证集困惑度。结果连同 `(avg_bits, total_bits)` 组成适应度。
3. **约束处理**：采样/生成个体后先检验 bit 约束，不合格即丢弃，不进入评估。
4. **初始种群**：随机采样满足约束的若干个体（规模 `population_size`），立即评估，缓存结果避免重复计算。
5. **选择**：按困惑度升序排序，保留前 `top_k` 作为精英与父代池。
6. **交叉**：在父代中采样两条染色体，逐层二选一生成子代（概率 `crossover_prob` 控制是否交叉，否则直接复制父代）。
7. **变异**：对子代每层以 `mutation_prob` 概率随机换成该层的其它合法 bit，增加探索性。
8. **迭代**：生成新一代直至人口填满，循环 `generations` 轮，输出全程困惑度最佳个体。

## 设计取舍
- **搜索 vs. 代价**：困惑度评估昂贵，采用小人口+少代数+缓存重复评估，适合快速筛选；若需要更高质量可增大人口/代数或采用温柔的 mutation。
- **约束显式筛掉**：在生成阶段直接拒绝不合格个体，避免无效评估开销。
- **确定性评估**：关闭随机 bit 分配与噪声，保证同一染色体评估稳定；与随机搜索相比更利于排序。
- **粗粒度成本模型**：以参数量×bit 近似模型大小/算力，便于快速筛选；如需更精确可替换为真实延迟/能耗测量。
- **搜索空间可控**：通过候选 bit 列表与层列表自动感知模型支持的 bit 选项，可轻松扩展到自定义层或更多 bit 级别。

## 与其他方法的对比（简述）
- 相较穷举：指数空间不可行，进化以交叉/变异的启发式在可行区域高效探索。
- 相较随机搜索：保留精英和交叉，可在局部结构上渐进优化；缓存重复评估减少浪费。
- 相较梯度式 NAS：无需可微化搜索空间，也不依赖额外超网络/代理模型，部署简单但收敛质量依赖超参与评估预算。

## 实践建议
- 预算有限时：减小 `max_eval_samples`、`population_size`、`generations`；提高 `mutation_prob` 增强探索。
- 追求质量时：增大人口/代数，适当降低 `mutation_prob`、提高 `crossover_prob`；可用分层候选 bit（先粗后细）。
- 约束调节：`max_avg_bits` 适合平均吞吐/存储约束；`max_bit_budget` 适合整体模型大小硬限制。可两者并用。
